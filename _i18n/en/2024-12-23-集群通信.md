## Buses and Communication Protocols

### PCIe

|                         | PCIe 1.0 | PCIe 2.0 | PCIe 3.0 | PCIe 4.0 | PCIe 5.0 | PCIe 6.0 |
| ----------------------- | -------- | -------- | -------- | -------- | -------- | -------- |
| Year                    | 2003     | 2007     | 2010     | 2017     | 2019     | 2021     |
| Transfer per lane(Gbps) | 2.5      | 5.0      | 8.0      | 16.0     | 32.0     | 64.0     |
| x16 bandwidth(GB/s)     | 4.0      | 8.0      | 15.8     | 31.5     | 63.0     | 121      |

Bandwidth calculation:

$$\text{x16 bandwidth(GB/s)} ≈\text{Transfer\ per\ lane(Gbps)} \times 16 / 8$$

### NVLink

NVLink is a bus and communication protocol developed and released by NVIDIA. It uses a point-to-point structure and serial transmission. It connects a central processing unit (CPU) and a graphics processing unit (GPU), and it can also interconnect multiple NVIDIA GPUs. Products that ship with NVLink have already been released, mostly for high-performance computing. The earliest, in 2016, was the Pascal-architecture GP100 chip and the Tesla P100 accelerator based on that chip, which was equipped with NVLink.

|                                     | NV Link 1.0 | NV Link 2.0 | NV Link 3.0 | NV Link 4.0 |
| ----------------------------------- | ----------- | ----------- | ----------- | ----------- |
| Year                                | 2014        | 2017        | 2020        | 2022        |
| Transfer per link(GB/s)             | 20+20       | 25+25       | 25+25       | 25+25       |
| Link number                         | 4           | 6           | 12          | 18          |
| Lane number per link                | 8           | 8           | 4           | 2           |
| Data rate per lan(Gbps)             | 20          | 25          | 50          | 100(PAM4)   |
| Total bidirectional bandwidth(GB/s) | 160         | 300         | 600         | 900         |

The H100 chip uses NVLink 4.0. Two H00 chips are interconnected by 18 NVLinks. Each link contains 2 lanes, and each lane supports a rate of 100 Gb/s PAM4, so the total bidirectional bandwidth is 900 GB/s.

NVSwitch uses 3.0. Each NVSwitch supports 64 ports, and each port runs at 50 GB/s.

A DGXH100 is built from 8 H100 chips and 4 NVSwitch chips (the NVLink counts are 5+4+4+5). The connection structure is shown below. On the other side of each NVSwitch in the figure, five 800G OSFP optical modules are attached. Take the first switch on the left as an example. The aggregate unidirectional bandwidth on the side connected to the GPUs is 4 Tbps (20NVLink\\*200Gbps), and the aggregate bandwidth on the side connected to the optical modules is also 4 Tbps (5\\*800Gbps), forming a `non-blocking network`. Note that the bandwidth quoted for an optical module is unidirectional, while AI chips generally quote bidirectional bandwidth.

### HCCS

The Ascend 910 AI processor is a high-performance AI processor developed by Huawei. The processors inside it are connected by HCCS (for example, A0~A3 form one HCCS). HCCS (`Huawei Collective Communication Server`) is the hardware form of HCCL (`Huawei Collective Communication Library`). HCCL provides high-performance collective communication between servers for deep learning training.

For the training product line, each machine has two HCCS rings, eight processors in total (A0~A7). Each HCCS has four processors. Processors on the same HCCS can exchange data; processors on different HCCS rings cannot communicate. That is, the Ascend 910 AI processors assigned to the same pod (if there are four or fewer) must lie on the same HCCS ring, or the job fails to run. ## Communication Algorithms<a id="sec-3"></a>

The common communication primitives are as follows:

+ **Point-to-Point Communication**: includes Send/Recv, and mainly carries out communication between two nodes.
+ **Broadcast**: broadcasts the data on one device to every other device.
+ **AllReduce**: aggregates data from all devices and then broadcasts it to every device.
+ **AllGather**: collects data from all devices and distributes it to all devices.
+ **ReduceScatter**: reduces the data and scatters the result across multiple devices.
+ **All-to-All**: every node (or process) sends data to all other nodes and, at the same time, receives data from all other nodes. In the end, every node holds the data collected from all the other nodes. It can also be viewed as a distributed `Transpose`.

A given communication primitive can be implemented by different communication algorithms, for example:

1. **Ring**: arrange the nodes in a ring topology. Each node communicates only with its two neighbors. In each communication step, data moves around the ring in a fixed direction, and the reduction or distribution is completed step by step. Each node's communication volume is $2 \cdot \text{DataSize} / \text{NumNodes}$, and the number of communication steps is $P-1$ ($P$ is the number of nodes).
2. **Mesh**: arrange the nodes on a two-dimensional or higher-dimensional grid. Each node communicates only with its neighbors above, below, to the left, and to the right. Communication proceeds in steps along the row direction and the column direction. The number of communication steps is $O(\sqrt{P}) $, which suits a large number of nodes.
3. **HD** (**Hierarchical Decomposition**): hierarchical optimization that splits communication into two levels, **intra-node communication** and **inter-node communication**. Intra-node communication uses shared memory or a high-speed link (such as `NVLink`); inter-node communication goes over the network (such as `InfiniBand`). Bandwidth is used efficiently: intra-node communication is much faster than inter-node communication. It applies to multi-machine, multi-GPU settings: distributed deep learning training and large-scale HPC.
4. **Tree**: organize the nodes as a tree. The root gathers and distributes the data. The tree may be a binary tree, a multi-way tree, and so on, matching the communication requirement. The number of communication steps is $O(\log P)$, which suits settings that need low latency.

| **Property** | **Ring** | **Mesh** | HD | **Tree** |
| -------------- | -------------------- | ---------------------- | -------------------- | -------------------- |
| **Topology** | Ring | Multidimensional grid | Hierarchical decomposition | Tree |
| **Communication complexity** | $O(P)$ | $O(\sqrt{P})$ | Depends on the hierarchy | $O(\log P)$ |
| **Where it fits** | Small-scale communication | Large-scale distributed training | Multi-machine multi-GPU, large-scale parallelism | Small messages, low latency |
| **Implementation complexity** | Simple | Fairly complex | High | Moderate |
| **Advantages** | Easy to implement, balanced communication | Scalable, load balanced | Uses hardware resources efficiently | Few communication steps, low latency |
| **Disadvantages** | Latency grows as the number of nodes grows | Complex to implement, and there are many communication steps | Depends on the hardware topology | Data distribution has to be designed precisely |
