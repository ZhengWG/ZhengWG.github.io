# Concurrency

Put simply, "concurrency" means that several operations proceed at the same time over an interval, and "multithreading" is one way to implement concurrency.

# Multithreading

## The Thread Concept

In `C++`, a thread is a function that can run independently:

```c++
auto f = []()  // 定义一个lambda表达式
{
  cout << "thread id:" << this_thread::get_id() << endl;
};

thread t(f);  // 启动一个线程：运行函数f
```

## Multithreaded Development

A simple example based on the basic `thread` class:

```c++
mutex out_lock;

void func(const char* name)
{
  thid_thread::sleep_for(100ms);
  lock_guard<mutex> guard{
    out_lock;
  };
  cout << "Thread: " << name << endl;
}

int main(){
  thread t1{func, "A"};
  thread t2{func, "B"};
  t1.join();
  t2.join();
}
```

A few details stand out:

1. A `thread` must be `join`ed before it is destroyed, or `detach`ed (giving up management of the thread). Otherwise the program exits abnormally.
2. Use a mutex (`mutex`) to lock `cout`, or the output is interleaved. A property of a mutex: a single mutex can be locked by only one thread. A mutex can only be default-constructed. It cannot be copied (or moved), and it cannot be assigned. The methods it provides are:
   1. `lock`: lock. If another thread already holds the lock, execution blocks.
   2. `try_lock`: try to lock. Return `true` if the lock is acquired, otherwise return `false`.
   3. `unlock`: release the lock (called by the thread that holds it).

The example above returns no data. If a result has to be retrieved after a thread runs, a semaphore or a condition variable is required.

```c++
void work(condition_variable& cv,
         	mutex& cv_mut,
         	bool& result_ready,
         	int& result)
{
  this_thread::sleep_for(2s)；
  result = 66;
  {
    unique_lock lock{cv_mut};
  	result_ready = true;
  }
  cv.notify_one();
}

int main()
{
  condition_variable cv;  // 条件变量
  mutex cv_mut; // 互斥量
  bool result_ready = false; // 结果状态变量
  int result; // 结果变量
  
  thread t1{work, ref(cv), ref(cv_mut), 
           	ref(result_ready), ref(result)}; // ref声明引用输入
  
  cout << "Waiting for something." << endl;
  unique_lock lock{cv_mut}; // 单一锁
  cv.wait(lock, [&] {
    return result_ready;
  });
  cout << "Answer: " << result << endl;
  t1.join();
}
```

As this shows, returning a function result requires extra definitions: a `condition variable`, a `unique lock`, a `result-status variable`, and a `result variable`. That is relatively cumbersome to use. `async` can simplify it (covered in detail below).

## Programming Techniques

1. Reading a const variable is safe in C++ multithreaded programming: use the const keyword often. **"Reading without writing means there is no data race"**.

2. Keep it to **"call only once"**: to stop an initialization function from running more than once, declare a variable of type **once_flag**, preferably static and global (so every thread can see it), as the initialization flag:

3. **Thread-local storage** (thread local storage): implemented with `thread_local`. The marked variable has an independent copy in each thread, that is, it is "exclusive to the thread":

   ```c++
   thread_local int n = 0; // 线程局部存储变量
   auto f = [&](int x) // 线程函数，捕获引用变量
   {
     n += x;
     cout << n;
   }
   
   int main(){
     thread t1{f, 10};
     thread t2{f, 20}; // 最终输出为10/20，互不干扰
   }
   ```

4. **Atomic variables**: in a multithreaded setting, an atomic variable means "indivisible". The operation either completes or does not complete, and it cannot be interrupted by another operation, so there is no competing read or write. Not every operation can be made atomic. Only some basic types are provided in atomic form, such as atomic_int and atomic_long:

   ```c++
   using atomic_bool = std::atomic<bool>;
   using atomic_int = std::atomic<int>;
   using atomic_long = std::atomic<long>;
   ```

   An atomic variable itself wraps the original type in a template class. The interface is the same, but **the copy constructor is disabled, so "=" cannot be used for assignment; only parentheses or braces can**.

   The most basic use of an atomic variable is as a thread-safe global counter or flag:

   ```c++
   static atomic_flag flag {false};
   static atomic_int n;
   
   auto f = [&](){
     auto value = flag.test_and_set(); // TAS检查原子标志量
     
     if (value) 
       cout << "flag has been set." << endl;
     else
       cout << "set flag by" << this_thread::get_id() << endl;
     n += 100; // 原子变量加法运算
     this_thread::sleep_for(n.load() * 10ms); // 使用时间字面量
   };
   
   thread t1(f);
   thread t2(f);
   
   t1.join(); // 等待线程结束
   t2.join();
   ```

## Async

Calling `thread` directly is a relatively "raw" way to use it, and it is more cumbersome. The `async()` function can be used instead, as in the example above:

```c++
int work()
{
  this_thread::sleep_for(2s);
  return 66;
}

int main(){
  auto fut = async(launch::async, work); // launch调用运行策略：新线程调用
  cout << "Waiting for something." << endl;
  cout << "Answer: " << fut.get() << endl; //get方法只能调用一次，采用移动方法
}
```

Note: if you do not explicitly take the return value of `async()` (the `future` object), it blocks synchronously until the task finishes (because the temporary object's destructor runs), and so `async` becomes `sync`. If the return value does not matter, `auto` can be used to avoid that:

```c++
std::async(task, ...); // 没有显式获取future，被同步阻塞
auto f = std::async(task, ...); // 只有上一个任务完成后才能被执行
```

## Promise

`Promise` is another way to use this. It is called a promise.

```c++
void work(promise<int> prom)
{
  this_thread::sleep_for(2s);
  prom.set_value(66);
}

int main()
{
  promise<int> prom;
  auto fut = prom.get_future();
  thread t1{work, move(prom)};
  cout << "Waiting for something." << endl;
  cout << "Answer: " << fut.get() << endl;
}
```

`promise` and `future` have to appear as a pair: the `promise` moves the data across threads, and the `future` retrieves the data, so the lifetime of the returned data does not have to be managed.

A `promise` and `future` pair can be used only once. The value cannot be set again, and it cannot be retrieved again.
