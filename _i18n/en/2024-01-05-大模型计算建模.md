# Preface<a id="sec-1"></a>

This post covers the computation and GPU memory usage of Transformer-style large models during training and inference. For large-model inference and training, computation determines the training or inference speed, and GPU memory usage determines how much data can be processed (more GPU memory allows more data or longer sequences to run in parallel). Large Language Models (LLMs) have broadly converged in model structure, and can be divided into two kinds: encoder-decoder and decoder-only. Mainstream chat models such as GPT, GLM, and LLaMA are all based on the decoder-only framework, and since the encoder and decoder differ little in model structure, this post analyzes the parameter count, computation, and GPU memory of the decoder-only framework.

# Parameter Count<a id="sec-2"></a>

A decoder-only model consists mainly of a leading `Embedding layer`, L \\* `Transformer Block`, and a final `logits` output layer. The key parameters of the model are:

-   number of transformer layers l
-   hidden size h
-   number of attention heads a
-   vocabulary size V
-   batch size b
-   sequence length s

The main structure is the Transformer Block, which has two parts: `self-attention` and the `FFN`.

The self-attention module's parameters include the weight matrices of Q/K/V, $W_Q$, $W_K$, $W_V$, the output projection $W_O$, and the biases. All four weight matrices have shape [h,h] and all biases have shape [h]. The Add & Norm layer has two trainable parameters, a scale parameter and a shift parameter, totaling 2h, so the self-attention module has $4h^2+4h+2h=4h^2+6h$ parameters.

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2024-01-05-%25E5%25A4%25A7%25E6%25A8%25A1%25E5%259E%258B%25E8%25AE%25A1%25E7%25AE%2597%25E5%25BB%25BA%25E6%25A8%25A1/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%A1%E7%AE%97%E5%BB%BA%E6%A8%A1_20240106_151846.png)

The FFN layer consists mainly of 2 linear layers plus an Add & Norm layer, and here we consider only the parameters of the linear layers. The two linear layers expand and reduce the dimension respectively: the first goes from h->4h and the second from 4h->h. A linear layer's parameters are mainly the weight matrix and the bias, so the total is: $2\*4\*h\*h+h+4h+2h=8h^2+7h$.

In sum, each transformer layer has $12h^2+13h$ parameters, so l transformer layers have $l(12h^2+13h)$ parameters. Note that some parameters, such as positional encoding, are omitted here, but they are usually small.

For the other two layers: the Embedding layer's parameters are determined by the vocabulary size V and the hidden size h: Vh. The final logits output layer is mainly a single linear layer plus a Softmax layer, and the output layer's linear matrix is usually shared with the Embedding layer's parameters. So these two layers together usually contribute Vh parameters. The trainable parameters of the whole model are therefore $l(12h^2+13h)+Vh$. When the hidden size h is large, the linear terms can be ignored, giving $12lh^2$. Taking LLaMA as an example:

| Actual parameters | Hidden size h | Layers l | Parameters 12lh^2 |
| 6.7B  | 4096 | 32  | 6442450944          |
| 13.0B | 5120 | 40  | 12582912000         |
| 32.5B | 6656 | 60  | 31897681920         |
| 65.2B | 8192 | 80  | 64424509440         |

# Computation<a id="sec-3"></a>

Computation is usually measured in FLOPs (floating point operations). Take matrix multiplication as an example: for matrices A and B, where A has shape 1xn and B has shape nx1, computing A @ B takes n multiplications and n additions, 2n floating-point operations in total, that is, 2n FLOPs. For an mxn matrix A and an nxk matrix B, the number of floating-point operations is 2mnk.

For the computation of LLMs, first analyze a single inference pass:

Suppose the input has shape [b, s] and passes through the embedding layer to give [b, s, h], with vocabulary size V. The matrix multiplication is $[b, s, V] x [V, h] -> [b, s, h]$, so the computation is 2bshV.

For the self-attention part:

1.  The input and output shapes of the three Q/K/V matrix multiplications are [b, s, h] x [h, h] -> [b, s, h], so the computation is $6bsh^2$.
2.  The input and output shapes of the $QK^T$ matrix multiplication are [b, a, s, per_head_hidden_size] x [b, a, per_head_hidden_size, s] -> [b, a, s, s], and the computation is $2bhs^2$.
3.  For score \\* V, the input and output shapes are [b, a, s, s] x [b, a, s, per_head_hidden_size] -> [b, a, s, per_head_hidden_size], and the computation is $2bhs^2$.
4.  For the linear layer after attention, the input and output are [b, s, h] x [h, h] -> [b, s, h], and the computation is $2bsh^2$.

Summing gives $8bsh^2 + 4bhs^2$.

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2024-01-05-%25E5%25A4%25A7%25E6%25A8%25A1%25E5%259E%258B%25E8%25AE%25A1%25E7%25AE%2597%25E5%25BB%25BA%25E6%25A8%25A1/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%A1%E7%AE%97%E5%BB%BA%E6%A8%A1_20240106_155923.png)

For the FFN layer, the input and output shapes of the two linear layers are:

1.  [b, s, h] x [h, 4h] -> [b, s, 4h], and the computation is $8bsh^2$.
2.  [b, s, 4h] x [4h, h] -> [b, s, 4h], and the computation is $8bsh^2$.

Summing gives $16bsh^2$.

Finally, in computing the logits, the matrix multiplication has input and output shapes [b, s, h] x [h, V] -> [b, s, V], and the computation is 2bshV.

In sum, the computation of a whole forward pass is $l(24bsh^2 + 4bhs^2) + 4bshV$. When the hidden size h is large (much larger than the sequence length s), the lower-order terms can be ignored, giving $24lbsh^2$. As shown earlier, the model has $12lh^2$ parameters, and if the number of input tokens is bs, then $24lbsh^2 / (12lbsh^2) = 2$. That is, during inference each token and each parameter can be approximated as requiring two floating-point operations.

For training, besides the forward pass there are also the backward gradient computation and the parameter update, and the backward pass costs twice the computation of the forward pass. So for training, each token and each parameter needs approximately 6 floating-point operations.

# GPU Memory Usage<a id="sec-4"></a>

During model inference, GPU memory is used mainly by two parts: the model parameters and the intermediate activations of the forward pass. For training there are also the gradients of the backward pass and the optimizer states. Here the optimizer is AdamW, the most commonly used for large-model training, and mixed-precision training is assumed by default.

In one training iteration, every trainable parameter has one gradient and 2 optimizer states (first and second moments). With mixed precision, during computation (forward pass and backward gradient computation) the weights and gradients are in FP16/BF16, taking 2 bytes each, but the parameter update in the backward pass needs a backup copy converted to FP32 precision, taking 4 bytes. The AdamW states are all stored in FP32, so the GPU memory per parameter is: $2+4+2+4+4+4 bytes$.

During the forward pass, the memory is mainly the model parameters and the intermediate activations. Some small buffers are ignored here, such as those of the embedding and output layers, because when h is large and l is deep, the intermediate activations of those layers are small. So the intermediate activations come mainly from the l transformer layers:

-   self-attention ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2024-01-05-%25E5%25A4%25A7%25E6%25A8%25A1%25E5%259E%258B%25E8%25AE%25A1%25E7%25AE%2597%25E5%25BB%25BA%25E6%25A8%25A1/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%A1%E7%AE%97%E5%BB%BA%E6%A8%A1_20240106_164428.png)
    
    1.  Computing Q/K/V requires saving X. The input X has shape [b, s, h] and dtype FP16/BF16, using 2bsh of GPU memory.
    
    2.  Computing $QK^T$: the two tensors Q and K have shape [b, s, h], 4bsh in total.
    
    3.  Computing softmax requires saving $QK^T$, $2bs^2a$ in total.
    
    4.  The dropout mask has the same shape as $QK^T$ and dtype bool, using $bs^2a$ of GPU memory.
    
    5.  Computing attention requires saving the score and V, which are $2bs^2a+2bsh$ respectively.
    
    6.  Computing the output projection and dropout requires saving X and the mask, which are $2bsh+bsh$ respectively.
    
    In sum, the total is $5bs^2a+11bsh$. Note, however, that in pure inference some tensors can actually be reused.

-   FFN ![img](/assets/img/recovered/365c3a60ba4274f5.png)
    
    1.  The input of the first linear layer uses 2bsh of GPU memory.
    
    2.  The activation function needs to save its input, using 8bsh of GPU memory.
    
    3.  The input of the second linear layer uses 8bsh of GPU memory.
    
    4.  The dropout mask input is bsh.
    
    The total is 19bsh. In addition, there are two normalization layers, each of which must save its input as intermediate activations, 2bsh each and 4bsh in total.

In sum, for an l-layer transformer model, the GPU memory used by intermediate activations is approximately $l(5bs^2a+34bsh)$.

In addition, LLM inference usually uses a KV cache to speed up inference, and the KV cache has two parts:

1.  Prefill phase: A prompt sequence is input, and a key cache and value cache are generated for every transformer layer, with a size matching the input prompt sequence.
2.  Decode phase: The KV cache is used and updated as words are generated one after another. There are usually two ways: one dynamically grows the cache by concatenation; the other allocates the maximum cache up front and updates it by offset, which avoids the performance cost of dynamic allocation.

Suppose the input sequence length is s and the output sequence length is n, with the KV cache stored in FP16/BF16. The peak GPU memory of the KV cache is then $b(s+n)h\*l\*2\*2=4blh(s+n)$, where the first 2 stands for K/V and the second 2 for bytes.
