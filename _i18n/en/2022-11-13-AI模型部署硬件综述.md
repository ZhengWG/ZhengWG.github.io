# Hardware<a id="sec-1"></a>

## GPU<a id="sec-1-1"></a>

A GPU (Graphics Processing Unit) is a microprocessor that performs image and graphics computation on personal computers, workstations, and some mobile devices. The concept was first introduced by NVIDIA in August 1999 with the release of the GeForce 256 chip. Early GPUs were used mostly for image computation (especially 3D graphics), such as hardware coordinate transformation and texture mapping for 3D environments. By how they connect to the system, GPUs fall into discrete GPUs and integrated GPUs. A discrete GPU is usually packaged on its own graphics card and has dedicated GPU memory, whereas an integrated GPU usually shares resources with the CPU, such as system memory. By target platform, GPUs can be divided into PC, server, and mobile GPUs.

The traditional GPU market (PC and server) is currently almost monopolized by foreign vendors. The revenue of the top three vendors, Nvidia, AMD, and Intel, makes up nearly the whole GPU industry's revenue, and Intel's revenue comes mainly from integrated graphics. In mobile GPUs, such as those in phones and tablets, the leading vendors are ARM, Qualcomm, and Apple. For most of the past 20-plus years, demand for GPUs came from video acceleration and 2D/3D games, but with the GPU's advantages in parallel processing and general-purpose computing, demand in artificial intelligence and edge computing is gradually taking off. For NVIDIA, 2021 revenue was 16.7 billion US dollars, of which gaming accounted for 47%, data centers for 40%, and professional visualization and autonomous driving for 9%. For the computing industry, GPUs are measured along three dimensions: generality, ease of use, and high performance. That is, the hardware architecture must be flexible enough, the barrier to development must be low so it is easy to get started, and the chip must offer high baseline performance and good price-performance. Domestic Chinese GPUs developed relatively late; the earliest GPU chip, the JM5400, was developed by Jingjiawei in 2014. Other relatively well-known vendors include Biren Technology, VeriSilicon, Denglin Technology, and HiSilicon.

### NVIDIA<a id="sec-1-1-1"></a>

In large data centers, artificial intelligence, and supercomputing, high-end GPUs are gradually becoming a necessity for compute throughput. NVIDIA holds more than 90% of the high-end GPU market. So far, NVIDIA has released the Volta, Ampere, and Hopper architectures for high-performance computing and AI training, with the corresponding GPUs V100, A100, and H100; their double-precision vector floating-point throughput ranges from 7.8TFLOPS to 30TFLOPS. The rest of this section focuses on NVIDIA's latest Hopper architecture. NVIDIA's GPU microarchitectures over the past decade evolved as follows: Tesla->Fermi->Kepler->Maxwell->Pascal->Volta->Turing->Ampere->Hopper.

Before introducing Hopper, here is a brief look at the basic unit of an NVIDIA GPU, the SM (streaming multiprocessor). Its basic structure is shown below (the composition of the SM differs somewhat between architectures):

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221005_164310.png)

The SM is regarded as the heart of the GPU. Its core units include:

-   CUDA Core: Before the Fermi architecture it was also called an SP (scalar processor core). It is the general-purpose compute unit and can perform a multiply-add with a single instruction. Depending on the supported data type, there are INT32, FP32, and FP64 CUDA Core units.
-   Tensor Core: Introduced after the Volta architecture and used mainly for matrix operations (MMA). It supports FP16/FP32 mixed precision.
-   LD/ST: short for Load/Store Unit, the memory access unit.
-   SFU: short for Special Function Unit, which handles special math functions such as sin/cos.
-   Warp Scheduler: The warp is NVIDIA's basic unit of thread scheduling, and every SM has warp schedulers to schedule warps.
-   Dispatch Unit: Sends the instructions issued by the warp scheduler to the cores (CUDA core, Tensor Core, LD/ST, SFU) for execution.
-   L0 Instruction Cache: The cache built into the SM.
-   Register File: The register resources, which are partitioned across the SMs.

Outside the SM are the Tensor Memory Accelerator (TMA), the L1 cache, and shared memory. The TMA can efficiently transfer large blocks of data between global memory and shared memory, copy data asynchronously, and so on.

The Hopper architecture is described in more detail in the [NVIDIA architecture whitepaper](https://www.nvidia.cn/lp/data-center/resources/download-hopper-arch-whitepaper/); the key points are summarized here.

1.  4nm process. For the H100 in the SXM4 form factor, power is 700W and memory bandwidth is 3TB/s. Compared with the A100, the H100's clock speed is 30% higher and its number of SMs is 1.2x higher.
2.  Key SM features: Each SM is organized into 4 quadrants. Each quadrant contains 16 INT32 units, which support mixed-precision INT32/INT8/INT4 processing; 32 FP32 units, which support FP16/FP32 mixed precision; 16 FP64 units; 384 32-bit registers; 8 LD/ST units; 4 SFU units; and 1 Tensor Core.
3.  Key Tensor Core features: It uses the fourth-generation Tensor Core architecture, which doubles the computational throughput. The Tensor Core supports the FP8, FP16, BF16, TF32, FP64, and INT8 MMA data types. FP8 is a newly added data type, and the FP8 Tensor Core supports multiple accumulator data types and output types (see the figures below). The Transformer Engine can also choose between FP8 and FP16 precision, which raises throughput (~2x) while maintaining accuracy.
    
    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221006_231604.png)
    
    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221006_231829.png)

4.  Shared memory/L1 cache: The H100 has 256KB of L1 cache per SM versus 192KB per SM on the A100, and shared memory can go up to 228KB.
5.  Overall performance comparison: Combining the clock speed and SM count from item 1 with the Tensor Core throughput gain and the Transformer Engine from item 3, the H100's compute throughput is about 6x that of the A100.

### Biren Technology<a id="sec-1-1-2"></a>

Relatively little public information exists on domestic Chinese GPUs. Taking [Biren Technology](https://www.birentech.com/BR100.html) as an example, the current BR100 series includes two chips, the BR100 and the BR104. The core specifications of the BR100 are:

-   2048 TOPS INT8 / 1024 TOPS BF16 / 512 TOPS TF32+ / 256 TOPS FP32
-   PCIe 5.0 interface at 128GB/s, and BLink (the counterpart of NvLink)
-   300+MB of cache, 2.3TB/s of external I/O bandwidth, 64 channels of encoding and 512 channels of decoding, 2.5D CoWoS packaging, 7nm process, 550W power

The overall chip architecture is shown below. It has several main parts: the compute units, a 2D-mesh on-chip network, the HBM2e memory system, the media engine, the PCIe 5.0 interface, and the BLink interconnect interface:

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221008_225402.png)

The chip's core compute unit, the SPC, is analogous to the GPU's SM. Each SPC contains 16 EUs (Execution Units), and each EU has 16 general-purpose compute cores (V-cores) and one Tensor core. At the instruction-set level it uses SIMT, together with an NVIDIA-like C-Warp cooperative concurrency scheme, so it is compatible with CUDA. It uses a distributed shared L2 cache connected through the on-chip network.

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221008_230952.png)

### Google TPU<a id="sec-1-2-1"></a>

Google first proposed the first-generation TPU (Tensor Processing Unit) in 2016, positioning it as an AI accelerator application-specific integrated circuit (ASIC). As of 2022 the TPU has reached TPUv4: ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_163930.png)

Google's TPU was first released in 2017; see [A reading of the Google TPU paper](https://johneyzheng.top/posts/Goolge-TPU%E8%AE%BA%E6%96%87%E8%A7%A3%E8%AF%BB/) for details. Its structure is as follows. The main compute unit is the Matrix Multiply unit, whose inputs come from two parts: the FIFO (weight matrix) and the UB (input data), and whose output goes to the accumulators (Accumulators). There are also dedicated nonlinear, Normalize, and Pool units. The design philosophy of the TPU architecture: `The philosophy of the TPU microarchitecture is to keep the matrix unit busy.`

The design framework of [TPU v4](https://cloud.google.com/tpu/docs/system-architecture-tpu-vm) is as follows:

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_220729.png)

Each v4 TPU chip contains two TensorCores. Each TensorCore has four MXUs, one vector unit, and one scalar unit.

### Ascend<a id="sec-1-2-2"></a>

[Ascend](https://www.hiascend.com/zh/) AI accelerator cards currently come in three main types: Atlas 300I Duo, Atlas 300I Pro, and Atlas 300V Pro. Taking the 300I Duo as an example:

-   7nm process, 280 TOPS INT8, 140 TFLOPS FP16, 48GB of LPDDR4x with 408GB/s total bandwidth, ECC support, **very strong** encoding and decoding capability, PCIe Gen4.0, compatible with 3.0/2.0/1.0

At the architecture level it uses the in-house Da Vinci architecture. The key points are the compute unit design (Cube/Vector/Scalar Unit) and the multi-level cache design (UB/L1/L2), which "happen to coincide" with the TPU's design approach:

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_221926.png)

### Kunlun<a id="sec-1-2-3"></a>

[Kunlun](https://www.kunlunxin.com.cn) chips currently have two architectures, XPU-K and XPU-R (for reference material, see [Baidu Kunlun An AI processor for diversified workloads](https://ieeexplore.ieee.org/document/9220641/metrics#metrics)):

-   First-generation architecture, XPU-K, taking the K200 as an example: 14nm process, 256 TOPS@INT8 compute throughput, 64TFLOPS@FP16, PCIe 4.0x8, HBM high-speed memory, 512GB/s memory bandwidth

### Cambricon<a id="sec-1-2-4"></a>

As of this writing (2022/11), the [Cambricon](https://www.cambricon.com/) website lists three generations of accelerator cards: MLU 1xx, MLU 2xx, and MLU 3xx. The parameters of the latest chip, the MLU370, are as follows:

-   MLU370: 7nm process, 256 TOPS@INT8 compute throughput, MLUarch3 architecture, LPDDR5 support, MLU-Link interconnect

Little material is available on the MLUarch3 architecture. Its evolution is as follows:

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_153514.png)

Chiplet technology is a chip design and manufacturing technique: functionality is split into small pieces with reusable IP blocks that can be combined modularly. It can raise yield and lower production cost, and some vendors regard it as the key to extending Moore's Law. Many chip vendors have proposed their own chiplet technologies, such as TSMC's bumpless System on Integrated Chip, AMD's Zen2 architecture, and Intel's Foveros 3D-stacking heterogeneous system integration scheme.

At the architecture design level, Cambricon has released several architectures since 2014:

-   DianNao: A Small-Footprint High-Throughput Accelerator for Ubiquitous Machine-Learning. It first proposed the NFU (Neural Function Units) structure, which has three parts: NFU-1, the multiplier array; NFU-2, the adder tree; and NFU-3, the activation unit. There are also three buffers, which store the input data, the weights, and the computed results. ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_160240.png)
    
    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog//2022-11-13-AI%25E6%25A8%25A1%25E5%259E%258B%25E9%2583%25A8%25E7%25BD%25B2%25E7%25A1%25AC%25E4%25BB%25B6%25E7%25BB%25BC%25E8%25BF%25B0/AI%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E8%BD%AF%E7%A1%AC%E4%BB%B6%E7%BB%BC%E8%BF%B0_20221113_160259.png)

-   DaDianNao: A Machine-Learning Supercomputer. A multi-core version of DianNao that uses a multi-chip design to run large models out of on-chip memory.
-   ShiDianNao: Shifting Vision Processing Closer to the Sensor. It integrates operations such as video encoding and decoding.
-   PuDianNao: A Polyvalent Machine Learning Accelerator. The last work in the DianNao line, it supports 7 machine learning algorithms: neural networks, linear models, support vector machines, decision trees, naive Bayes, K-nearest neighbors, and K-means clustering.
-   Cambricon-X: An Accelerator for Sparse Neural Networks. It adds support for sparse networks.

# Software<a id="sec-2"></a>

NPU scheduling differs greatly from traditional CPU scheduling strategies, and the goal of high-performance NPU computing is to get the maximum speedup from an NPU-specific strategy. The topics involved include operating-system knowledge such as kernel drivers, memory management, system calls, and context switching. Many of the problems encountered are similar too, such as cache utilization and DDR latency.
