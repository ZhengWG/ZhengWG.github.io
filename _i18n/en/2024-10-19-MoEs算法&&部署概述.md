##### MoEs (Mixture-of-Experts Models)

MoEs were first proposed in the [Switch Transformer](https://arxiv.org/abs/2101.03961). The core structure consists of sparse MoE layers and a gating network, or router:

$$y = \sum_{i=1}^{n} g_i(x) \cdot f_i(x)$$

where $n$ is the number of experts, $g_i(x)$ is the gating network's weight for the $i$-th expert, and $f_i(x)$ is the output of the $i$-th expert for the input.

- Sparse MoE layers:

  These layers replace the feed-forward network (FFN) layers of a traditional Transformer model. An MoE layer contains a number of "experts" (for example, 8), and each expert is itself an independent neural network. In practice, these experts are usually FFNs, but they can also be more complex network structures, or even MoE layers themselves, forming a hierarchical MoE structure.

- Gating network or router

  The gating network is usually a small neural network that generates expert weights from the input features: the output $g(x)$ commonly takes the form of a $Softmax$.

  This part decides which tokens are sent to which expert. For example, in the figure below, the token "More" might be sent to the second expert, while the token "Parameters" is sent to the first expert. Sometimes a token can even be sent to more than one expert. How tokens are routed is a key point in using MoEs, because the router consists of learned parameters and is pretrained together with the rest of the network.

The difficulty of accelerating MoEs is that:

their branching structure makes computation inefficient, and as the number of experts grows they must be deployed in a distributed fashion across multiple GPUs or machines, which adds communication overhead. MoE models usually need multiple parallelism strategies, `DP/PP(MP)/TP/EP`, and these strategies often have to be combined.

DeepSpeed's combination of parallelism strategies is as follows. The figure below uses a single MoE layer to explain how hybrid parallelism is used. Assume there are 16 GPUs in total and 8 experts. The parallel modes are designed separately for expert and non-expert modules, as follows:

-   For the non-expert parameter modules:
    -   4-way data parallelism is used, so these parameters are replicated 4 times.
    -   Within each data-parallel replica, 4-way tensor parallelism is used.
-   For the expert parameter modules:
    -   8-way expert parallelism is used.
    -   Each expert's parameters are split with 2-way tensor parallelism.
