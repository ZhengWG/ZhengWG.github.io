# Preface<a id="sec-1"></a>

Garbage collection is essential to every language. Its core function is "memory management": preventing "memory leaks". A "memory leak" means that a program fails to release memory that is no longer in use, usually because of a design problem that makes the program lose control of memory it has used, which wastes memory. This article reviews the garbage collection mechanism in **Python**.

# Garbage Collection Methods<a id="sec-2"></a>

The most commonly used mechanism in **Python** is **reference counting**. In **Python** everything is an object, and every variable is a reference to an object. So the most intuitive idea is to collect garbage by counting references to an object: `when an object's reference count is 0, the object is unreachable and needs to be collected`. A simple example follows:

```python
import sys

a = []

# 两次引用，一次来自 a，一次来自 getrefcount
print(sys.getrefcount(a))

def func(a):
    # 四次引用，a，python 的函数调用栈，函数参数，和 getrefcount
    print(sys.getrefcount(a))

func(a)
# 两次引用，一次来自 a，一次来自 getrefcount，函数 func 调用已经不存在
print(sys.getrefcount(a))

########## 输出 ##########
2
4
2
```

**Python** also allows you to perform garbage collection manually with `del a + gc.collect()`, for example:

```python

import gc

show_memory_info('initial')

a = [i for i in range(10000000)]

show_memory_info('after a created')

del a
gc.collect()

show_memory_info('finish')
print(a)

########## 输出 ##########

initial memory used: 48.1015625 MB
after a created memory used: 434.3828125 MB
finish memory used: 48.33203125 MB

---------------------------------------------------------------------------
NameError                                 Traceback (most recent call last)

     11 
     12 show_memory_info('finish')
---> 13 print(a)

NameError: name 'a' is not defined
```

Of course, in **Python** a reference count of 0 is not a necessary and sufficient condition for garbage collection to start, because of **circular references**. Inside a function, if a and b reference each other, then after the function call ends a and b no longer have any meaning from the program's point of view and should be removed. In practice, however, the memory is still occupied in this case and has to be released manually:

```python

import gc

def func():
    show_memory_info('initial')
    a = [i for i in range(10000000)]
    b = [i for i in range(10000000)]
    show_memory_info('after a, b created')
    a.append(b)
    b.append(a)

func()
show_memory_info('before collected')
gc.collect()
show_memory_info('finished')

########## 输出 ##########

initial memory used: 49.51171875 MB
after a, b created memory used: 824.1328125 MB
before collected memory used: 824.1328125 MB
finished memory used: 49.98046875 MB
```

Calling `gc.collect()` explicitly cleans up the memory. This shows that besides "reference counting", the garbage collection mechanism in **Python** has other methods:

-   Mark-sweep: the mark-sweep algorithm starts from a single node and traverses the graph, marking all reachable nodes. When the traversal ends, the unmarked nodes are the "unreachable nodes". Finally, these "unreachable nodes" are garbage collected. In the implementation, "Python" uses a doubly linked list and only considers container objects (only these objects can have circular references).
-   Generational collection: generational collection is an optimization whose core is to optimize the garbage collection strategy. It works by dividing objects into three generations: newly created objects are generation 0, and each time an object survives it is moved to the next generation. The garbage collection threshold of each generation is specified separately. When the number of objects added to the collector minus the number of objects deleted reaches the threshold of a generation, garbage collection is started for that generation. The idea behind the design is that newly created objects are more likely to be collected, while the longer an object has survived, the more likely it is to keep surviving. This approach saves computation and improves the performance of Python.

# Debugging Memory Leaks<a id="sec-3"></a>

A tool for debugging memory leaks: objgraph, a package that makes it easy to visualize reference relationships. `show_refs()` generates a clear reference graph. In the following example you can see a clear graph of the mutual references:

```python

import objgraph

a = [1, 2, 3]
b = [4, 5, 6]

a.append(b)
b.append(a)

objgraph.show_refs([a])
```

`show_backrefs()` can likewise generate a graph of the references pointing to an object:

```python
import objgraph

a = [1, 2, 3]
b = [4, 5, 6]

a.append(b)
b.append(a)

objgraph.show_backrefs([a])
```
