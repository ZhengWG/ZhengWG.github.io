# Preface<a id="sec-1"></a>

Unit tests are very important for disciplined program development, and especially for test-driven development (TDD). The core of a unit test is to write tests that verify that a module works correctly; typically you specify an input and check whether the output matches expectations. The commonly used testing libraries in Python include unittest, nose, and pytest. This article focuses on [unittest](https://docs.python.org/3/library/unittest.html), which is built into Python and modeled on PyUnit.

# Basic Usage (unittest)<a id="sec-2"></a>

Here is a simple example of using the `unittest` library:

```python
import unittest

# 将要被测试的排序函数
def sort(arr):
    l = len(arr)
    for i in range(0, l):
        for j in range(i + 1, l):
            if arr[i] >= arr[j]:
                tmp = arr[i]
                arr[i] = arr[j]
                arr[j] = tmp


# 编写子类继承unittest.TestCase
class TestSort(unittest.TestCase):

   # 以test开头的函数将会被测试
   def test_sort(self):
        arr = [3, 4, 1, 5, 6]
        sort(arr)
        # assert 结果跟我们期待的一样
        self.assertEqual(arr, [1, 3, 4, 5, 6])

if __name__ == '__main__':
    ## 如果在Jupyter下，请用如下方式运行单元测试
    unittest.main(argv=['first-arg-is-ignored'], exit=False)

    ## 如果是命令行下运行，则：
    ## unittest.main()

## 输出
..
----------------------------------------------------------------------
Ran 2 tests in 0.002s

OK
```

Let's analyze the code above. The `TestSort` class inherits from `unittest.TestCase`, and functions whose names start with `test` are run as test functions. Inside a test function, the usual assertion functions are `assertEqual()/assertTrue()/assertFalse()/assertRaise()`.

# mock<a id="sec-3"></a>

`mock` is the most central part of unit testing. The core idea of `mock` is to use a fake object in place of an object that the function or module under test needs. It applies when the test of one module depends on other modules: with `mock` you can create fake objects so that the module under test can be tested. In `Python mock`, this is mainly done with the `mock/MagicMock` objects:

```python
import unittest
from unittest.mock import MagicMock

class A(unittest.TestCase):
    def m1(self):
        val = self.m2()
        self.m3(val)

    def m2(self):
        pass

    def m3(self, val):
        pass

    def test_m1(self):
        a = A()
        a.m2 = MagicMock(return_value="custom_val")
        a.m3 = MagicMock()
        a.m1()
        self.assertTrue(a.m2.called) #验证m2被call过
        a.m3.assert_called_with("custom_val") #验证m3被指定参数call过

if __name__ == '__main__':
    unittest.main(argv=['first-arg-is-ignored'], exit=False)

## 输出
..
----------------------------------------------------------------------
Ran 2 tests in 0.002s

OK
```

In the code above, `test_m1` tests the `m1()` function, and `m1()` calls the `m2/m3` functions. What `mock` does here is replace the `m2` function with one that returns the concrete value "custom_val", and replace `m3` with an empty function. This use of `mock` is the simplest approach, and it can only specify the return value. In addition, you can use `Mock Side Effect` to design the input/output behavior of a `mock` function:

```python

from unittest.mock import MagicMock
def side_effect(arg):
    if arg < 0:
        return 1
    else:
        return 2
mock = MagicMock()
mock.side_effect = side_effect

mock(-1)
1

mock(1)
2
```

The `Mock Side Effect` above implements a simple function that returns different values depending on whether the input is less than 0.

# patch<a id="sec-4"></a>

`patch` provides a very convenient way to `mock`. Through the `decorator/context manager` pattern, you can quickly mock the function or module you need. For example, you can `mock` the default `sort` function and then design the corresponding `return_value/side_effect`:

```python
from unittest.mock import patch

@patch('sort')
def test_sort(self, mock_sort):
    ...
    ...
```

`patch` can also `mock` a class member function. For example, a class's complicated initialization function can be mocked as a function that returns `None`, which avoids the complicated initialization:

```python
with patch.object(A, '__init__', lambda x: None):
      …
```

# High-Quality Unit Tests<a id="sec-5"></a>

How do you design high-quality unit tests? Some key factors are:

-   Coverage (`Test Coverage`): measures the percentage of statements in the code that are covered. It can be said that raising the coverage of a code module is, to a certain extent, equivalent to raising the correctness of the code.
-   Modularity: the core is to develop code from the testing perspective, and to think about how to modularize the code.

For example, a piece of code with `pre-processing/sort/post-processing` can be described simply as follows:

```python
def work(arr):
    # pre process
    ...
    ...
    # sort
    l = len(arr)
    for i in range(0, l):
        for j in range(i + 1, j):
            if arr[i] >= arr[j]:
                tmp = arr[i]
                arr[i] = arr[j]
                arr[j] = tmp
    # post process
    ...
    ...
    Return arr
```

However, the code above is clearly hard to test module by module. After modularizing the code, it can be designed as:

```python
def preprocess(arr):
    ...
    ...
    return arr

def sort(arr):
    ...
    ...
    return arr

def postprocess(arr):
    ...
    return arr

def work(self):
    arr = preprocess(arr)
    arr = sort(arr)
    arr = postprocess(arr)
    return arr
```

Based on the code above, the corresponding unit tests can be designed as follows:

```python
from unittest.mock import patch

def test_preprocess(self):
    ...

def test_sort(self):
    ...

def test_postprocess(self):
    ...

@patch('%s.preprocess')
@patch('%s.sort')
@patch('%s.postprocess')
def test_work(self,mock_post_process, mock_sort, mock_preprocess):
    work()
    self.assertTrue(mock_post_process.called)
    self.assertTrue(mock_sort.called)
    self.assertTrue(mock_preprocess.called)
```
