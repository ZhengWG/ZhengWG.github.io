# Development Environment

## The Compiler

A C++ compiler is a tool that turns C++ source code into machine code. Different platforms and systems support different C++ compilers. A few mainstream C++ compilers are:

+ [GCC (GNU Compiler Collection)](https://gcc.gnu.org/projects/cxx-status.html):

  Cross-platform, commonly used on Linux, integrated with the GNU toolchain, and strong at optimization. It suits high-performance computing and embedded development. Basic usage:

+ Clang:

  Cross-platform, with native support on macOS. It compiles quickly, integrates with the LLVM toolchain, and its error messages are friendly. It suits development and debugging.

+ MSVC:

  Only Windows. It is provided together with Visual Studio, integrates performance-analysis tools, and suits Windows application development.

Basic usage (GCC/Clang as the example):

```bash
# Compile and link
# --std: select the C++ standard
# -Wall: enable all warnings
# -O2: 
# -Iinclude: add an include path
# -Llib: add a library path
# -lmy_library: link the library
g++ -std=c++11 -Wall -O2 -Iinclude -Llib -o my_program main.cpp lib.cpp -lmy_library

# Generate debug information
g++ -g -o my_program my_program.cpp

# Generate the preprocessed file
g++ -E my_program.cpp > output.i
```

## The Working Environment

Take VSCode as the example:

1. Install the basic environment

   Install the compiler:

   ```bash
   sudo apt-get install g++
   # brew install g++
   # brew install clang
   ```

   Install the C/C++ extension in VSCode

2. Configure the build environment

   VSCode is configured through `tasks.json/launch.json/c_cpp_properties.json`:

   ```bash
   my_project/
   ├── .vscode/
   │   ├── tasks.json
   │   ├── launch.json
   │   └── c_cpp_properties.json
   ```

   `task.json` mainly defines the build task, with GCC as the example:

   ```json
   {
     "version": "2.0.0",
     "tasks": [
       {
         "label": "build",
         "type": "shell",
         "command": "g++",
         "args": [
           "-g",
           "-std=c++11",
           "-o",
           "${workspaceFolder}/bin/my_program",
           "${workspaceFolder}/src/main.cpp"
         ],
         "group": {
           "kind": "build",
           "isDefault": true
         },
         "problemMatcher": ["$gcc"],
         "detail": "Generated task by VSCode"
       }
     ]
   }
   ```

   

   `launch.json` mainly defines the debug configuration, for example on `GDB/LLDB`:

   ```json
   {
     "version": "0.2.0",
     "configurations": [
       {
         "name": "Debug C++",
         "type": "cppdbg",
         "request": "launch",
         "program": "${workspaceFolder}/bin/my_program",
         "args": [],
         "stopAtEntry": false,
         "cwd": "${workspaceFolder}",
         "environment": [],
         "externalConsole": false,
         "MIMode": "gdb",
         "setupCommands": [
           {
             "description": "Enable pretty-printing for gdb",
             "text": "-enable-pretty-printing",
             "ignoreFailures": true
           }
         ],
         "preLaunchTask": "build",
         "miDebuggerPath": "gdb",
         "logging": {
           "trace": true,
           "traceResponse": true,
           "engineLogging": true
         }
       }
     ]
   }
   ```

   

   `c_cpp_properties.json` configures IntelliSense and the header search path

   ```bash
   {
     "configurations": [
       {
         "name": "Linux",
         "includePath": [
           "${workspaceFolder}/include",
           "/usr/include",
           "/usr/local/include"
         ],
         "defines": [],
         "compilerPath": "/usr/bin/g++",
         "cStandard": "c11",
         "cppStandard": "c++17",
         "intelliSenseMode": "gcc-x64"
       }
     ],
     "version": 4
   }
   ```

   

## Build Tools

The core role of a build tool is to **automate** and **standardize** the development process, for example automatic compilation and linking, dependency management, and cross-platform support. Common build tools include:

| **Build tool** | **Characteristics** | **Where it fits** |
| :------------ | :------------------------------------------- | :------------------------------- |
| **CMake** | Cross-platform, powerful, widely used | Cross-platform projects, large projects |
| **Bazel** | High performance, multi-language, complex configuration | Large projects, multi-language projects |
| **Ninja** | Focused on build speed, suited as a low-level build tool | Fast builds, as a backend for other tools |
| **Autotools** | A traditional tool, supports automatic configuration, and is gradually being replaced | Unix/Linux development, legacy projects |
| **SCons** | Based on Python, flexible configuration, relatively slow builds | Small and medium projects that need flexible configuration |
| **Premake** | Based on Lua, simple configuration, supports several build systems | Small and medium projects that need a simple configuration |
| **Gradle** | Based on Groovy/Kotlin, multi-language, weaker C++ support | Multi-language projects, mixed Java and C++ projects |
| **Xcode** | Integrated in the Xcode IDE, limited to Apple platforms | macOS/iOS development |

The basic usage below uses CMake as the example. It usually has two parts:

1. Writing CMakeLists.txt

   ```cmake
   project(MyProject CXX)  # 定义项目名称和语言
   add_executable(my_program main.cpp) # 添加可执行文件
   add_library(my_library STATIC my_library.cpp) # 添加库
   include_directories(include) # 包含头文件目录
   target_link_libraries(my_program my_library) # 链接库
   target_link_libraries(my_program my_library) # 设置编译选项
   set(CMAKE_CXX_STANDARD 11) # 设置变量
   ```

2. Compiling with CMake

   The working directory for the CMakeLists.txt file above is:

   ```bash
   MyProject/
   ├── CMakeLists.txt
   ├── include/
   │   └── my_library.h
   ├── src/
   │   ├── main.cpp
   │   └── my_library.cpp
   ```

   Compile and run on that basis:

   ```bash
   mkdir build
   cd build
   cmake ..  # produce the Makefile
   cmake --build .
   ./my_program
   ```

### Development Tools

#### Formatters

`Clang-Format` is the code formatter commonly used in the LLVM project.

Format from the command line:

```bash
clang-format -i my_file.cpp  							  # format a single file
clang-format -i *.cpp        							  # format every .cpp file
clang-format -style=Google -i my_file.cpp   # select a code style
```

Configuration file:

```bash
# .clang-format
BasedOnStyle: Google
IndentWidth: 4
```

#### Debuggers

Basic use of GDB (GNU Debugger); LLDB is similar:

```bash
g++ -g -o my_program my_program.cpp # generate debug information at compile time
gdb ./my_program # start GDB
```

Common commands:

+ `break <line number>`: set a breakpoint.

- `run`: run the program.
- `next`: step over (do not enter the function).
- `step`: step into (enter the function).
- `print <variable>`: print a variable's value.
- `backtrace`: show the call stack.
- `quit`: quit GDB.

# Unit Testing

Common C++ unit-testing libraries are `Boost.Test` and `Catch2`.

1. Boost.Test

   Basic usage:

   ```c++
   #define BOOST_TEST_MAIN
   #include <boost/test/unit_test.hpp>
   #include <stdexcept>
   
   void test(int n)
   {
     if (n == 42) {
       return;
     }
     throw std::runtime_error(
       "Not the answer");
   }
   
   BOOST_AUTO_TEST_CASE(my_test) // 定义测试用例
   {
     BOOST_TEST_MESSAGE("Testing");
     BOOST_TEST(1 + 1 == 2);
     BOOST_CHECK_THROW( // 检查抛出异常
       test(41), std::runtime_error);
     BOOST_CHECK_NO_THROW(test(42));
   
     int expected = 5;
     BOOST_TEST(2 + 2 == expected);
     BOOST_CHECK(2 + 2 == expected); // 与BOOST_TEST不同的是：不会尝试输出表达式内容
   }
   
   BOOST_AUTO_TEST_CASE(null_test) {}
   ```

2. Catch2

   Catch2 has these advantages:

   + A single header is enough to use it. There is no install step and no link step, so it is simple.
   + It can optionally use the sectional style of BDD (Behavior-Driven Development).
   + On failure it can optionally drop straight into the debugger (on Windows and macOS).

   Usage:

   ```c++
   #define CATCH_CONFIG_MAIN
   #include "catch.hpp"
   #include <stdexcept>
   
   void test(int n)
   {
     if (n == 42) {
       return;
     }
     throw std::runtime_error(
       "Not the answer");
   }
   
   TEST_CASE("My first test", "[my]")
   {
     INFO("Testing");
     CHECK(1 + 1 == 2);
     CHECK_THROWS_AS(
       test(41), std::runtime_error);
     CHECK_NOTHROW(test(42));
   
     int expected = 5;
     CHECK(2 + 2 == expected);
   }
   
   TEST_CASE("A null test", "[null]") {}
   ```

3. perf: it can sample at a fixed frequency, that is, run pstack many times, and obtain the function call pattern. For example `perf top -K -p xxx` sorts by CPU use and looks only at user-space calls, which makes it easy to find the function that consumes the most CPU.

4. Analysis at the source level needs some "intrusive" means, such as **Google Performance Tools**, including `CPUProfiler` and `HeapProfiler`. Install them as follows:
   ```bash
   apt-get install google-perftools
   apt-get install libgoogle-perftools-dev
   ```

   Basic usage:

   + ProfilerStart() starts profiling and stores the data in the given file.

   + ProfilerRegisterThread() allows a thread to be profiled.

   + ProfilerStop() stops profiling.

     A simple use is shown below. Here `shared_ptr` implements automatic management. Using `void*` and a null pointer, arbitrary code can run when the smart pointer is destroyed (a simple `RAII` idiom):

   ```c++
   auto make_cpu_profiler =            // lambda表达式启动性能分析
   [](const string& filename)          // 传入性能分析的数据文件名
   {
     ProfilerStart(filename.c_str());  // 启动性能分析
     ProfilerRegisterThread();         // 对线程做性能分析
   
     return std::shared_ptr<void>(     // 返回智能指针
       nullptr,                        // 空指针，只用来占位
       [](void*){                      // 删除函数执行停止动作
           ProfilerStop();             // 停止性能分析
       }   
     );  
   };
   ```

   Test the facility with `make_cpu_profiler`:

   ```c++
   auto cp = make_cpu_profiler("case1.perf");     // 启动性能分析
   auto str = "neir:automata"s;
   
   for(int i = 0; i < 1000; i++) {               // 循环一千次
     auto reg  = make_regex(R"(^(\w+)\:(\w+)$)");// 正则表达式对象
     auto what = make_match();
     assert(regex_match(str, what, reg));        // 正则匹配
   }
   ```
