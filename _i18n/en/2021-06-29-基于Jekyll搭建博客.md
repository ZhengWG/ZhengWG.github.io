# Blog Setup Options<a id="sec-2"></a>>

A static site suits a blog that focuses on content. For common options for building a blog as a static site, see: [The 11 Most Popular Static Site Generators](https://www.cnblogs.com/buyz/p/10935831.html). Octopress/Jekyll support org-mode well and have plenty of resources, so I chose that solution. The blog platform is GitHub Pages, whose advantages are:

-   You can write posts locally
-   It is simple and lightweight

# Introduction to Jekyll<a id="sec-3"></a>

Based on: [jekyll-emacs](https://www.zmonster.me/2013/09/14/blogging-with-jekyll-emacs.html) and the [official Jekyll docs](https://jekyllrb.com/docs/). A fully featured Jekyll blog directory contains the following structure and files:

```sh
-- index.html # 网站首页文件
-- archives.html # 文章存档页面文件，文件名可改
-- categories.html # 文章分类页面文件，文件名可改
-- tags.html # 文章标签页面文件，文件名可改
-- about.html # “关于我”页面文件，文件名可
-- rss.xml或atom.xml # 博客地图，SEO优化
-- _config.yml # Jekyll博客配置文件
-- _layouts # 博客模板目录
   -- default.html
   -- post.html
-- _includes # 可复用的公用模板文件目录，例如博客的导航条，不是必须的，
             # 但分离出各个页面的共有部分可以使得模板更易读，结构更清晰
   -- footer.html
   -- footer.html
   -- <other file to include in template>
-- _posts # 文件存放目录
   -- 2013-09-08-test.html
   -- <other posts>
-- assets/ # 其他博客文件存放目录，如css，图片，js文件，以下目录结构为示例
   -- css
      -- style.css
   -- img
      -- favicon.ico
   -- js
      -- blog.js
-- _doc # yaml/json/csv/tsv文件，可定义通用的数据：valuable/options
```

Notes on the core files:

-   \_config.yaml: the `_config.yaml` file is the Jekyll blog's configuration file. In it you can set the blog name, blog description, author name, and so on, and these can be **used as variables in templates**. If you configure the blog from a template, this is mainly the file you need to edit:

    ```python
    # Handing Reading
    encoding: utf-8

    # Basic
    title: main_title
    subtitle: sub_title
    description: description

    permalink: /:year/:month/:title/

    # Format
    highlighter: rouge

    # supported colors: blue, green, purple, red, orange or slate. If you need clear, leave it empty.
    cover_color:

    # The blog button should not be removed.
    blog_button:
        title: Blog
        description: Visit blog

    # Navigation buttons in the front page.
    nav:
        # - {title: Another Button, description: A button, url: 'http://example.com'}

    # Pagination
    plugins: [jekyll-paginate]
    paginate: 10
    paginate_path: "page/:num/"

    # Comment
    comment:
        # disqus: ****
        # duoshuo:

    # Default: 对应目录下的默认页面配置信息
    default:

    # Social
    social:
        weibo: ****
        github: ****
        twitter: ****
        mail: ****

    # Google Analytics
    ga:
        # id: your_ga_id
        # host: your_host
    ```

# Deploying the Blog<a id="sec-4"></a>

This post uses the Jekyll theme [jekyll-theme-chirpy](http://github.com/cotes2020/jekyll-theme-chirpy). The installation steps are as follows:

```sh
# clone, 命名为username.github.io,方便GitHub Pages部署
git clone git@github.com:cotes2020/jekyll-theme-chirpy.git username.github.io
# 安装gem依赖
bundle
# 初始化
bash tools/init.sh
# 删除现有文件
rm -rf .travis.yaml _posts/* docs
# 修改_config.yaml，主要修改：url/avatar/timezone/lang/social等内容
# 具体可参考个人博客：https://github.com/ZhengWG/ZhengWG.github.io
# 添加博客文件(markdonw/html格式)到_posts
# 本地预览
bundle exec jekyll s
```

For remote deployment to GitHub Pages: because GitHub Pages runs in safe mode, extra plugins cannot be applied. So I deploy with GitHub Actions, mainly based on the ./github/workflows/pages-deploy.yaml file (it is ignored by default, so you need to modify the .gitignore file). After you push to the remote repository, GitHub builds the site and generates the gh-pages branch. Finally, change the GitHub Pages setting: **Settings->Options->Github Pages**, and change the publishing source from master to gh-pages.

# Blog Comments<a id="sec-5"></a>

The comment options for Jekyll are briefly introduced below:

-   Disqus: supported by default in most Jekyll templates, but the drawback is that it needs a VPN to bypass the firewall
-   NetEase Cloud comments: requires your own domain name
-   Duoshuo: the service has been discontinued
-   gitment/gittalk: use GitHub issues, but they seem to carry the risk of requiring overly broad permissions
-   Valine: a comment system based on [LeanCloud](https://leancloud.cn) that is fairly convenient: [official site](https://valine.js.org).

Below, the comment configuration for Disqus and Valine is introduced. In the end I went with Valine (since it needs no VPN):

-   Disqus comments: [jekyll-theme-chirpy](http://github.com/cotes2020/jekyll-theme-chirpy) supports Disqus comments by default. To configure it: register and sign in at [Disqus](https://disqus.com/), which provides a social comment system. Follow the prompts (skipping the paid plan); after registering and signing in you get a shortname. Then modify the `_config.yaml` file:

    ```sh
    disqus:
      comments: true
      shortname: 'shortname'
    ```

    The resulting comments look like this:

    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/1.jpg)
-   Valine comments: to set up the Valine comment system, first create an application on the [LeanCloud site](https://leancloud.cn). After registering, create an application and name it:

    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/build_blog_20210717_165359.png)

    Then get the application's credentials: Application -> Settings -> Application Credentials:

    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/1626512245847.jpg)

    Also set the Web security domain: Application -> Settings -> Security Center:

    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/build_blog_20210717_165954.png)

    After creating the application, add Valine support in your local blog project. First create the variables in the `_config.yaml` file:

    ```sh
    valine_comment:
    enable: true
    # app_id
    leancloud_appid: *****************
    # app_key
    leancloud_appkey: *****************
    # placeholder
    placeholder: "请在下面评论："
    ```

    Then create `valine.html`, which by default goes in the `_includes` folder (note: remove the `\` escape character before `\{\%}`):

    ```js
    \{\% if site.valine_comment.enable %}
        <div id="comments"></div>
        <script src="//cdn1.lncld.net/static/js/3.0.4/av-min.js"></script>
        <script src='//unpkg.com/valine/dist/Valine.min.js'></script>
        <script>
        new Valine({
            el: '#comments',
            app_id: '{{ site.valine_comment.leancloud_appid }}',
            app_key: '{{ site.valine_comment.leancloud_appkey }}',
            placeholder: '{{ site.valine_comment.placeholder }}',
            visitor: true
        });
    </script>
    \{\% endif %}
    ```

    Finally, include the `valine.html` file wherever you want it to load, such as `page.html` and `post.html` in the `_layouts` folder:

    `page.html` (note: remove the `\` escape character before `\{\%}`):

    ```js
    \{\% if site.valine_comment.enable and page.comments %}
    <div class="row">
      <div class="col-12 col-lg-11 col-xl-8">
        <div class="pl-1 pr-1 pl-sm-2 pr-sm-2 pl-md-4 pr-md-4">

          \{\% include valine.html %}

          </div> <!-- .pl-1 pr-1 -->
        </div> <!-- .col-12 -->
      </div> <!-- .row -->
    \{\% endif %}
    ```

    `post.html` (note: remove the `\` escape character before `\{\%}`):

    ```js
    \{\% if site.valine_comment.enable and page.comments %}
      \{\% include valine.html %}
    \{\% endif %}
    ```

    Finally, you get the comment result:

    ![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/build_blog_20210717_173023.png)

# Google Analytics<a id="sec-6"></a>

Google Analytics can be used to monitor the site. Sign in at the [GA site](https://analytics.google.com/analytics/web) (which requires a VPN), and create an account and a property. Note that in the new version you need to choose the UA-related option under advanced options:

![img](https://cdn.jsdelivr.net/gh/ZhengWG/Imgs_blog/2021-06-29-%E5%9F%BA%E4%BA%8EJekyll%E6%90%AD%E5%BB%BA%E5%8D%9A%E5%AE%A2/2.jpg)

Finally you get the `track-id（UA-\*\*\*\*)`: Account -> Property. Modify the `_config.yaml` file:

```sh
google_analytics:
id: 'UA-*******'
```
