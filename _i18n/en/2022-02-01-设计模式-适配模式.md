# Concept<a id="sec-1"></a>

The Adapter pattern converts the interface of one class into another interface that the client expects, so that two classes that could not work together because of incompatible interfaces can work together. That is, the Adapter pattern serves to:

-   Convert interfaces: turn an existing interface (or method) into another interface
-   Wrap an existing class with a new interface
-   Match an old component to a new interface

The Adapter pattern has three main roles:

-   Target: the target interface you expect, i.e. the interface to convert to
-   Adaptee: the role to be converted, i.e. what you want to convert into the target role
-   Adapter: the core role of the pattern, responsible for converting and wrapping the adaptee into the target

Its advantages are:

-   It lets two unrelated classes run together, acting as an intermediate converter
-   It improves class reuse
-   It is flexible and does not break the existing system

Its disadvantages are:

-   If the existing system is not well designed (for example, Target is a concrete class rather than an abstract class or interface), the Adapter pattern is hard to implement
-   Excessive use of adapters easily makes code confusing: for example, you see that interface A is called, but internally interface B is actually called

# Design Template<a id="sec-2"></a>

The framework model of the Adapter pattern:

```python
from abc import ABCMeta, abstractmethod


class Target(metaclass=ABCMeta):
    """目标类"""
    @abstractmethod
    def function(self):
        pass


class Adaptee():
    """源对象类"""
    def special_function(self):
        print("被适配对象的特殊功能")


class Adapter(Adaptee, Target):
    """适配器"""
    def function(self):
        print("进行功能转换")
```
