An Overview of Speculative Decoding

Paper

MEDUSA: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads A Hitchhiker’s Guide to Speculative Decoding

Motivation

The decode phase of an LLM is usually limited by GPU memory bandwidth (memory-bandwidth-bound), because decode generates only a single token at a time, which leaves computational efficiency low.

One way to improve the computational efficiency of decode is to raise the arithmetic intensity of a single inference step and reduce the number of decode iterations. The design idea is to use a lightweight draft model to predict multiple tokens and then have the original model refine the generated tokens, which reduces the total computation without losing accuracy.

Key Points

The MEDUSA strategy is:

Multiple heads are added after the last layer’s hidden states. During actual inference, consecutive heads can generate multiple consecutive tokens, and the original model finally confirms the multiple candidates.

For computing multiple tokens, Tree-Attention is used to compute attention.

Some design details in actual deployment:

  1. Head efficiency: More heads can increase the number of tokens per inference step, and if they are fully accepted by the original model, efficiency is higher. But more heads make training harder, and if the draft model’s prediction accuracy is not high, some compute and GPU memory is wasted. In experiments, 3-4 heads give a large gain, and in some common setups 6-8 heads also give a large gain.

  2. KV cache design: For the original model’s verification of multiple tokens, the Lookahead scheduling design can reduce recomputation of the KV cache for proposal tokens and GPU memory copies.
