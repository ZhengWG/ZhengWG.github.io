Python’s basic data structures are the list, tuple, dict (dictionary), and set.

Basic Data Structures

  • A list is dynamic: its length is not fixed, and elements can be freely added, removed, or modified
  • A tuple is static: its length is fixed, and elements cannot be added, removed, or modified
  • Compared with lists and tuples, dictionaries perform better; in particular, lookup, insertion, and deletion all complete in constant time
  • A set is essentially the same as a dictionary, except that a set has no key-value pairs; it is an unordered collection of unique elements

Lists and Tuples

  • Difference in storage between lists and tuples: a list takes more space than a tuple (16 bytes more), made up of two parts: a pointer to the corresponding element (8 bytes), and the allocated length (8 bytes), which lets Python track the list’s space usage in real time and allocate extra space promptly when it runs out.

  • Performance of lists versus tuples: a tuple is a lighter-weight data structure than a list and is faster. In addition, Python’s garbage collection mechanism (covered later) temporarily caches the memory of some static objects, such as tuples, when they are no longer used and are small. So the next time Python needs a tuple of the same size, it does not have to send a request to find memory, which speeds up the program. For indexing, the difference between the two is very small.

Dictionaries and Sets

  • How dictionaries and sets work:

    • Initialization: the internal structure of both a dictionary and a set is a hash table; a dictionary just adds a value to each key. To use space better, the hash table keeps the indices separate from the hash values, keys, and values:

      Indices (sparse):

      None index None None index None …

      Entries (dense):

      hash0 key0 value0
      hash1 key1 value1
      hash2 key2 value2
    • Insertion: when an element is inserted into a dictionary or set, Python first computes the key’s hash value and then ANDs it with the mask value (mask = PyDicMinSize - 1): index = hash(key) & mask. The index value is a position in the hash table. If that position in the Indices table is empty, the element is inserted there. If it is occupied, Python compares the hash values and the keys of the two elements:
      • If both are equal, the element already exists; if the values differ, the value is updated.
      • If either is not equal, a “hash collision” occurs: the keys are different but the hash values are the same. The simplest remedy is linear probing or quadratic probing to find an empty slot (the real implementation is of course optimized, which we do not cover here).
    • Lookup: use the hash value to find the position in the Indices table directly, and from it the position of the data. Then compare the hash value and key of the element at that position; if they are equal, return it; otherwise keep probing until the element is found or an exception is raised.
    • Deletion: on deletion, Python temporarily assigns a special value (a marker) to the element at that position, and removes it only when the hash table is next resized. This is done mainly to save operation time. To keep it efficient, the hash table inside a dictionary or set normally keeps at least 1/3 of its space free. As elements keep being inserted, when the free space drops below 1/3, Python obtains a larger block of memory and expands the hash table. In that case all elements in the table are rearranged.
