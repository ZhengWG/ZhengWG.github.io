C++ Overview

What defines C++: C++ is a multi-paradigm, general-purpose programming language.

C++ supports “object-oriented programming”, “generic programming”, and “functional programming”:

  • Object-oriented: the core is abstraction and encapsulation. Tasks are completed through communication and cooperation among objects that are highly cohesive and loosely coupled.
  • Generic programming: the core is “everything is a type”. Code is reused through templates rather than inheritance.
  • Functional programming: the core is “everything is callable”. Data is processed through a series of consecutive or nested function calls.

Lifecycle and Programming Paradigms

A C++ program goes through several stages from “birth” to “death”: coding, pre-processing, compiling, and running.

  • Pre-processing: executed by the Pre-processor, whose purpose is text substitution. Preprocessor directives all begin with the symbol #, as in #include, #define, and #if. A #define macro has no notion of scope and takes effect globally.

  • Compiling: the work done here is “compilation” and “linking”, which produces machine code the computer can recognize. Commonly used features are “attributes” and “static assertions”.

Data Types and Keywords

  • const: a variable defined with const can only be an integer or an enumeration (a #define macro has no data type and is simple text substitution, so type checking is impossible). What const does is prevent modification and make the program more robust, and save space by avoiding unnecessary memory allocation. From the assembly point of view, a constant defined with const is only given a memory address, rather than an immediate value as with #define, so #define leads to several copies while const does not.

A non-const variable is extern by default, while a const object is by default local to its file. To access it from elsewhere, you must declare it extern explicitly, and it must be initialized. const and pointers:

If const is to the left of *, const modifies the variable the pointer points to, that is, the pointee is constant. If const is to the right of *, const modifies the pointer itself, that is, the pointer itself is constant.

  • volatile: it means “unstable” or “changeable”. When volatile modifies a const variable, the compiler does not apply optimizations with side effects when it generates binary machine code: it does not replace the const value with a constant, and instead reads the value from memory. volatile disables compiler optimizations, so unless it is necessary, use volatile sparingly.

  • mutable: it modifies a member variable and allows a const member function to modify it. Changes to a mutable variable do not affect the constness of the object, but they may “quietly” modify or corrupt the object, so use it as little as possible.

Memory Management

Basic Concepts

Heap:

The heap is the region where memory is allocated dynamically. Once allocated, memory must be released manually, otherwise it causes a memory leak. Two allocation/deallocation pairs are involved:

  • new and delete operate on the free store, which is generally a subset of the heap.

  • malloc and free operate on the heap.

1
2

  // C++
  auto ptr = new std::vector<int>();

In actual memory allocation, the allocator has to consider how much unallocated memory the program currently has. When memory runs short, it has to request new memory from the operating system. Releasing memory is not just a matter of marking it as unused. For contiguous blocks of unused memory, the memory manager usually has to merge them into one block so that later, larger allocation requests can be satisfied.

Without garbage collection, memory must be released manually, and memory can become fragmented (freeing memory leaves non-contiguous blocks that cannot be merged).

Stack:

In the context of memory management, the stack is the region for the local variables and call data produced during function calls. This stack is very similar to the stack data structure: both are “last-in-first-out” (LIFO).

In C++ function calls, local variables use the stack for memory management. Any function can, according to the architecture’s conventions, use only the stack space above the stack pointer at the time the function was entered. When a function calls another function, it also pushes the arguments onto the stack (we ignore the case of passing arguments in registers here), then pushes the address of the next assembly instruction onto the stack and jumps to the new function. After entering, the new function first does some necessary saving work, then adjusts the stack pointer to allocate the space needed for its local variables, then executes the code in the function. When it finishes, it uses the address the caller pushed onto the stack to return to the caller’s unexecuted code and continue. The memory for local variables lives on the stack, together with the other data the function needs to execute. When the function finishes, this memory is naturally released.

Characteristics of the stack:

  1. Allocation on the stack is extremely simple: just move the stack pointer.

  2. Deallocation on the stack is also extremely simple: just move the stack pointer when the function finishes.

  3. Because of the last-in-first-out execution order, memory fragmentation cannot occur. The data usually has a fixed, known size.

RAII (Resource Acquisition Is Initialization):

RAII, short for “Resource Acquisition Is Initialization”, lets C++ manage memory effectively without a garbage-collection mechanism like Java’s. Its core idea is to bind the acquisition and release of a resource (such as memory, a file handle, or a lock) to the lifetime of an object.

The core mechanisms of RAII:

  1. Resource acquisition: acquire the resource in the object’s constructor.

  2. Resource release: release the resource in the object’s destructor.

  3. Scope management: the lifetime of the resource is controlled by the scope of the object. When the object leaves its scope, its destructor is called automatically and the resource is released correctly.

Common applications of RAII:

Resource type RAII implementation Standard implementation
Dynamic memory Smart pointers (std::uniqueptr, std::sharedptr) Supported by the C++ standard library
File handle Custom file management std::fstream
Thread lock std::lockguard, std::uniquelock Supported by the C++ standard library
Database connection Database connection class Supported by third-party libraries
Network resource Socket management class Supported by third-party libraries

Lvalues and Rvalues

  • Lvalue

  • An lvalue is an expression that has an address and can persist.

  • It is usually on the left side of an assignment operator, but not always.

  • It can be manipulated through references.

Characteristics: addressable: its address can be taken (with the & operator) / modifiable (if it is not a constant).

  • Rvalue

  • An rvalue is a temporary value whose address cannot be accessed directly through a reference.
  • It is usually on the right side of an assignment operator.
  • An rvalue may be a literal, a temporary variable, or the result of an expression.

Characteristics: not addressable: its address cannot be taken with & (except through a type conversion) / short-lived: the lifetime of an rvalue is usually very short, typically valid only while the expression is being evaluated.

Pointers

A pointer comes from C. It is essentially a memory address index that represents a small region of memory and supports reading and writing memory directly. Because pointers map completely onto the computer hardware, they are efficient but also bring many problems: accessing invalid data, out-of-bounds pointers, memory that is never released, and so on.

A smart pointer wraps a raw pointer based on RAII and overloads the * and -> operators, so it is used just like a raw pointer.

Smart pointers fall into three kinds: unique_ptr, shared_ptr, and weak_ptr. A smart pointer is in fact an object. It automatically manages the pointer it was initialized with and releases the memory automatically when it leaves its scope, and you must not call delete on it. An uninitialized pointer defaults to a null pointer. Initializing with a factory function is recommended.

uniqure_ptr relies on C++ move semantics and forbids copying. Basic usage:

The difference between shared_ptr and uniqure_ptr is that its ownership can be shared safely, that is, it supports copy assignment and can be held by several owners. shared_ptr supports safe sharing because it uses “reference counting” internally. shared_ptr costs more to store and manage, and it has the circular reference problem:

    • Operator overloading: operator overloading lets developers give user-defined types (such as classes and structs) operations like those of built-in types. It is done by defining special operator functions. Some points to note:
      1. Must use member functions of the class: unary operators (such as +) and the assignment operator must be member functions of the class.
      2. Friend functions can be used: for example, « and » are usually implemented as friend functions.
      3. Do not abuse operator overloading: make sure the semantics of an overloaded operator match expectations.

  1. Virtual functions and polymorphism: a virtual function is a mechanism C++ provides to support runtime polymorphism (also called dynamic polymorphism). It allows a derived class to override a member function of the base class, and chooses the appropriate function to call at runtime based on the actual object type. A member function declared with virtual in the base class is a virtual function, and a derived class can override it. The C++ compiler generates a virtual function table for the class, which is used at runtime to call the correct function according to the object’s type. When a virtual function is called, the program determines at runtime which version to call (the base-class version or the derived-class version).

    How virtual functions work:

    Virtual function table (vtable):

    • Every class that has virtual functions generates a virtual function table (vtable).
    • The table stores pointers to all the virtual functions of the class.
    • An object finds the vtable through a pointer, and thereby determines which function to call.

    Advantages: it provides dynamic polymorphism and simplifies code design. It supports interface abstraction and suits object-oriented design patterns.

    Disadvantages: looking up the vtable at runtime has some performance overhead. It increases the memory overhead of the class, since every object contains a pointer to the vtable. It adds complexity: you need to pay attention to whether the destructor is virtual (to prevent the wrong destructor from being called when a derived-class object is deleted through a base-class pointer, which causes a memory leak).
