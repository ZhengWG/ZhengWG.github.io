First, a few words about Python. The languages I know best are mainly C++ and Python. Especially since I started working, Python has been my main working language most of the time. This of course has to do with my field of work: one of Python’s strengths is that it suits data analysis, so it is widely used in artificial intelligence, machine learning, and similar fields. Popular machine learning frameworks today, such as TensorFlow and PyTorch, all provide Python interfaces. But the low-level matrix computation relies on C++, because C++ is fast and runs more efficiently.

Python is a dynamic language. Its advantages are that it is easy to pick up and convenient to debug, and beginners can focus on programming objects and ways of thinking rather than on external factors such as syntax and types. Its disadvantages: execution efficiency is low, since a Python program needs an interpreter to turn its code into something the specific operating system understands, and a dynamic language is less stable than a static one, especially once the system becomes complex, when its stability cannot be guaranteed.

Basic Data Structures

Python’s basic data structures include the list, tuple, dict, and set. A brief introduction:

  • A list is dynamic: its length is not fixed, and elements can be freely added, deleted, and modified
  • A tuple is static: its length is fixed, and elements cannot be added, deleted, or modified
  • Compared with lists and tuples, dicts perform better; in particular, lookup, insertion, and deletion all complete in constant time
  • A set is basically the same as a dict, except that a set has no key/value pairing and is an unordered collection of unique elements

Key characteristics:

  • Differences in how lists and tuples are stored:

    A list takes more storage space than a tuple (16 bytes more), mainly because of two parts: a pointer that points to the corresponding element (8 bytes), and the allocated length (8 bytes), which makes it easy to track the use of the list’s space in real time and allocate extra space promptly when the space runs out.

  • Performance comparison of lists and tuples:

    Compared with lists, tuples are a lighter-weight data structure and perform faster. In addition, with Python’s garbage collection mechanism (covered later), for static variables such as tuples, when one is no longer used and does not take up much space, Python temporarily caches that memory. So the next time memory of the same size is created, Python does not need to issue a request to find memory, which speeds up the program. For indexing operations, the difference between the two is very small

  • How dicts and sets work:

    • Initialization: the internal structure of both dicts and sets is a hash table, with the difference that dicts also have keys/values. To make better use of space, though, the hash table keeps the indices separate from the hashes, keys, and values: Indices (sparse):

      None index None None index None …

      Entries (not sparse):

      hash0 key0 value0
      hash1 key1 value1
      hash2 key2 value2
    • Insertion: when inserting an element into a dict/set, Python first computes the hash of the key and then does an AND with the mask (mask=PyDicMinSize - 1): index=hash(key) & mask. The index value is a position in the hash table. If that position in the Index table is empty, the element is inserted there. If it is occupied, Python compares whether the hashes and the keys of the two elements are equal:
      • If both are equal, the element already exists, and if the values differ, the value is updated.
      • If either one is not equal, a “hash collision” occurs, meaning the keys are different but the hashes are the same. The simplest remedy is to look for an empty slot by linear probing or quadratic probing (the internal implementation is of course optimized, which we do not care about here)
    • Lookup: go straight to the position in the Index table from the hash and then find the position of the data; then compare the hash and the key of the element at that hash table position, and return it directly if they are equal; otherwise keep searching until it is found or an exception is raised.
    • Deletion: on deletion, Python temporarily assigns a special value to the element at that position (as a marker) and removes it only when the hash table is resized. This is mainly to save operation time. To keep it efficient, the hash table in a dict or set usually keeps at least 1/3 of its space free. As elements keep being inserted, when the free space falls below 1/3, Python obtains a larger block of memory and enlarges the hash table. In that case all the elements in the table are laid out again.

Function Decorators and Closures

  • Introduction to decorators:

    They are used to “mark” functions in the source code and enhance a function’s behavior in some way. A decorator is itself a callable object whose argument is a function (the decorated function). A decorator may process the decorated function and return it, or replace it with another function or callable object. So one key feature of decorators is that they can replace the decorated function with another function; the second is that decorators run immediately when the module is loaded (not when the function is called).

def make_averager2():
    count = 0
    total = 0
    
    def averager(new_value):
        nonlocal count, total
        count += 1
        total += new_value
        return total / count
    
    return averager

    import time
import functools
    
# clock装饰器：打印函数的耗时情况
def clock(func):
    # functools.wraps:内置装饰器，作用是协助构建行为良好的装饰器
    # 此处将func的相关属性复制到clocked函数中
    # 其他常用的标准库装饰器：
    # functools.lru_cache: 能够将耗时函数结果保存，避免传入相同的参数时重复计算。
    @functools.wraps(func)
    def clocked(*args, **kwargs):
        t0 = time.time()
        # func为自由变量
        result = func(*args, **kwargs)
        elapsed = time.time() - t0
        name = func.__name__
        arg_list = []
        if args:
            # 定位参数
            arg_list.append(', '.join(repr(arg) for arg in args))
        if kwargs:
            # 关键字参数
            pairs = ['%s=%r' % (k, w) for k, w in sorted(kwargs.items())]
            arg_list.append(', '.join(pairs))
        arg_str = ', '.join(arg_list)
        print('[%.8fs] %s(%s) -> %r' % (elapsed, name, arg_str, result))
        return result
    return clocked
    
    
# 参数化clock装饰器
    
DEFAULT_FMT = '[{elasped:0.8f}s] {name}({args}) -> {result}'
    
# 本质上创建了一个装饰器工厂函数
def clock2(fmt=DEFAULT_FMT):
    def decorate(func):
        def clocked(*_args):
            t0 = time.time()
            _result = func(*_args)
            elasped = time.time() - t0
            name = func.__name__
            args = ', '.join(repr(arg) for arg in _args)
            result = repr(_result)
            print(fmt.format(**locals())) # fmt中引用clocked的局部变量
            return _result # 返回被装饰函数的返回值
        return clocked
    return decorate
    
    
if __name__ == '__main__':

    def snooze(seconds):
        time.sleep(seconds)
    
    for i in range(3):

    def snooze2(seconds):
        time.sleep(seconds)

  • del and garbage collection: CPython’s garbage collection mainly relies on reference counting, that is, every object keeps count of how many references point to it. When the reference count drops to zero, the object is destroyed immediately. The del statement deletes a name, not an object. An object is garbage collected only when the deleted variable held the last reference to the object, or when the reference can no longer reach the object.

Abstract Base Classes

  • Abstract base classes:

    A class that defines pure virtual functions. A pure virtual function usually provides only the interface and no concrete implementation; the concrete implementation must be supplied by overriding it in derived classes. An abstract base class is an incomplete class and cannot be instantiated. Its purpose is to improve the maintainability and reusability of code. The commonly used abstract base classes are the ones in collections.abc:

    import abc
    
class Tomola(abs.ABC):
    
    @abc.abstractmethod
    def load(self, iterable):
        # 抽象方法：load，从可迭代对象中添加元素
    
    @abc.abstractmethod
    def pick(self):
        # 抽象方法：pick，随机删除元素，并返回
        # 如实例为空，则返回'LookupError'
    
    def loaded(self):
        # 如果至少存在一个元素则返回True，否则返回False
        return bool(self.inspect())
    
    def inspect(self):
        # 返回一个有序元组，由当前元素构成
        items = []
        while True:
            try:
                items.append(self.pick())
            except LookupError:
                break
    
        self.load(items)
        return tuple(sorted(items))

  • The register approach:

    The base class’s register method can be used as a decorator (Python version>3.3) to register a class as a virtual subclass of the abstract base class. A virtual subclass does not inherit any methods from the abstract base class, and the program does not check at runtime whether it conforms to the abstract base class’s interface, but it needs to implement all the methods it requires itself.

Concurrency Details

  • Blocking I/O and the GIL:

    The CPython interpreter itself is not thread-safe, so it needs a global interpreter lock (GIL), which allows only one thread at a time to execute Python bytecode. As a result, a Python process usually cannot use multiple CPU cores at the same time. However, all the blocking I/O functions in the Python standard library release the GIL so that another thread can run.

    • How the GIL works: it is essentially related to Python’s memory management, such as the reference counting that Python uses to manage objects, mentioned above. With multiple threads, reference counting could become confused, leaving one thread unable to access data, so the GIL is needed to avoid this kind of memory management risk. The mechanism is that while a single thread is executing it locks the GIL to prevent other threads from executing; in the meantime the lock state of the GIL is polled by interval checks (the interval is not entirely consistent), forcing the current thread to release the GIL so that other threads get a chance to execute.
