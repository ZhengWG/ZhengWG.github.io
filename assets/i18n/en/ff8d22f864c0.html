Preface

A context manager helps to allocate and release resources automatically. The most typical example is the with statement:

1
2
3

for x in range(10000000):
    with open('test.txt', 'w') as f:
        f.write('hello')

It is equivalent to:

1
2
3
4
5

f = open('test.txt', 'w')
try:
    f.write('hello')
finally:
    f.close()

As you can see, the structure with with is more concise. Context managers are usually used for opening and closing files, opening and closing databases, acquiring and releasing thread locks, and similar operations. They ensure that used resources are released promptly, which effectively improves the safety of a program. In principle there are two kinds of context managers, which are functionally the same:

  • Generator-based context managers: convenient and concise, suitable for small and medium-sized programs
  • Class-based context managers: more flexible, suitable for large-scale system development

Class-Based Context Managers

For a class-based context manager, the key is to define a few key methods:

  • __init__: the initialization method that creates the class
  • __enter__: returns the resource to be managed
  • __exit__: usually contains operations that release or clean up resources, such as closing a file

Take FileManager, a context manager for opening and closing a file, as an example:

class FileManager:
    def __init__(self, name, mode):
        print('calling __init__ method')
        self.name = name
        self.mode = mode 
        self.file = None

    def __enter__(self):
        print('calling __enter__ method')
        self.file = open(self.name, self.mode)
        return self.file


    def __exit__(self, exc_type, exc_val, exc_tb):
        print('calling __exit__ method')
        if self.file:
            self.file.close()

with FileManager('test.txt', 'w') as f:
    print('ready to write to file')
    f.write('hello world')

## 输出
calling __init__ method
calling __enter__ method
ready to write to file
calling __exit__ method

In addition, the __exit__ method can be used to manage exceptions, through the parameters exec_type/exc_val/exc_tb, which stand for exception_type/exeception_value/traceback. class Foo:
    def __init__(self):
        print('__init__ called')        

    def __enter__(self):
        print('__enter__ called')
        return self

    def __exit__(self, exc_type, exc_value, exc_tb):
        print('__exit__ called')
        if exc_type:
            print(f'exc_type: {exc_type}')
            print(f'exc_value: {exc_value}')
            print(f'exc_traceback: {exc_tb}')
            print('exception handled')
        return True

with Foo() as obj:
    raise Exception('exception raised').with_traceback(None)

# 输出
__init__ called
__enter__ called
__exit__ called
exc_type: <class 'Exception'>
exc_value: exception raised
exc_traceback: <traceback object at 0x1046036c8>
exception handled

Note, however, that __exit__ must return True at the end, otherwise the exception is still raised.

Generator-Based Context Managers

The decorator contextlib.contextmanager can be used to define a context manager that supports the with statement:

In the code above, file_manager() is a generator that returns the file object f, and after the with statement finishes, the finally block runs to close the file. There is no need to define the __enter__() and __exit__() methods here, but it depends on @contextmanager

from contextlib import contextmanager

@contextmanager
def file_manager(name, mode):
    try:
        f = open(name, mode)
        yield f
    finally:
        f.close()

with file_manager('test.txt', 'w') as f:
    f.write('hello world')
